### S8 in detail

The consent step needs a real signed-in haynesnetwork user, and only the owner can sign in as the owner
(Authentik with Plex). So every client below has an **owner step** (open a URL, sign in, approve) and a
**driver step** (run the client, verify from logs and the database). Each owner step is pushed to his
phone as one question at the moment it arises. An authorization code lives **60 seconds**
(DESIGN-050 D-03): the redirect URL must reach the client within a minute of Approve, or the exchange
answers `invalid_grant` and the step starts again.

Verification sources for every client: Loki `{app="haynesnetwork", container="main"} |= "[auth]"` and
`|= "[mcp] tool_called"` (the `consumer` field), and read-only SQL on a CNPG replica (OPS-016 §3).

1. **Claude Code from dev-env.** Driver: in a scratch directory (never the dev-env `haynesnetwork` hop
   entry), add the server under a distinct name (`hnet-public`, `https://haynesnetwork.com/mcp`,
   Streamable HTTP) with `NODE_OPTIONS=--dns-result-order=ipv4first`, start the authentication, and
   hand the owner the authorization URL. Owner: open it on his device, sign in if asked, check that the
   consent page says "Sends you back to localhost" (or `127.0.0.1`), Approve, and paste the browser's
   final `localhost` URL (the page itself will not load) into the Claude Code session, which he can
   drive from his phone (`agent-run --interactive`). Driver verifies: `client_registered` with a
   `Claude Code (…)` name, `consent_granted`, `token_issued`, a `tool_called` line with
   `oauth:<client_id>` for `unfinished`, and, after the 1-hour access token expires, a second call that
   succeeds with `token_refreshed` logged.
2. **Codex from dev-env.** Driver: register the server with Codex under the same distinct name, run
   `codex mcp login hnet-public` (it listens on `127.0.0.1:<port>`), and hand the owner the URL. Owner:
   approve and send back the browser's final `http://127.0.0.1:<port>/callback/…` URL. Driver: deliver
   it inside the pod with `curl` within the minute, then verify as for Claude Code (a `Codex` client,
   a tool call, a refresh). Remove both test registrations from the CLIs afterwards.
3. **ChatGPT (owner-driven end to end).** Owner: in ChatGPT's connector settings (Developer mode),
   create a connector with the MCP server URL `https://haynesnetwork.com/mcp` and OAuth
   authentication; when the haynesnetwork consent page opens, check that it says "Sends you back to
   chatgpt.com" and Approve. In a **new chat** with the connector enabled, ask the three US-13
   questions, then "I already watched \<title\>" for the title the driver names, then "undo that".
   The next day (or after an hour), ask once more. Driver: before the chat, pick the mark title by the
   live-test rule below and record its Plex state on the preferred server; verify `client_registered`
   (`ChatGPT`, redirect host `chatgpt.com`), `consent_granted`, `token_issued`, one `tool_called` per
   question with `oauth:<client_id>`, the `watch_marks` rows with `consumer = 'oauth:<client_id>'`, the
   Plex state identical after the mark and the undo, and `token_refreshed` on the later question.
   If ChatGPT stalls on the 405 GET, ship the empty-stream GET fallback (ADR-091 C-13) and repeat.
4. **A second user (AC-27).** There is no test account and the driver cannot make one, so this step is
   owner-run: a household member (or another Plex account the owner uses) signs in and connects any
   client, most simply by opening a fresh Claude Code authorization URL from step 1 in a browser signed
   in as that user and approving. Driver verifies: `consent_granted` for a user id that is not the
   owner's, and `unfinished` answering "Watch history isn't set up for your account yet." Then that
   user disconnects it.
5. **Disconnect (AC-28).** Owner: on **Connected apps**, disconnect the Claude Code test client.
   Driver: the next call from that client answers 401, `oauth_client_disconnected` is in the audit, and
   the row reads Disconnected without moving. Then disconnect the Codex test client the same way, and
   leave ChatGPT connected.
6. **Optional (DESIGN-050 Q-01).** If the owner wants it, the same with a claude.ai custom connector;
   record the result in OPS-016 either way.

**Live-test rule for marks:** a live `mark_watched` is only made on a title with **no unwatched
regular episode on the preferred server** (zero flips, so Plex does not change; the PLAN-068 S12
lesson), and it is followed by `undo_last_change`. The driver checks the preferred server's leaves
before and after. A non-owner mark is never exercised live in this plan: no non-owner account is
tracked until PLAN-070, and its no-Plex rule is proven by S4's recording-fake test.

## Invariants a reviewer must not let regress

1. The hop token is never accepted on `/mcp`, and a Delegated Token is never accepted on `/api/mcp`.
2. `/api/mcp` is never routed by an IngressRoute; the public surface needs no route change and gets none.
3. There is no owner gate, and the owner is never a default: an OAuth consumer answers only for its own
   token user's Tracked Account, an unmapped or untracked user gets "isn't set up", and no tool accepts
   an account or user id. Plex is written only when the Tracked Account is the Server Owner's.
4. A Delegated Token is never a login: it opens no session, and nothing but `/mcp` reads it (hard rule 5).
5. Tokens, codes, client secrets and PKCE verifiers are never logged or stored in the clear; log lines
   carry at most a 6-character hash fingerprint; tokens are stored only as SHA-256 hashes.
6. Stateless: no in-process token or session cache; every replica validates with a database lookup; no
   `Mcp-Session-Id`; a disconnect takes effect on the very next request.
7. Scopes are exactly `watch:read`, `watch:write` and `offline_access`, advertised and granted; nothing
   else ever appears in the metadata.
8. PKCE S256 and `state` are always required; `plain` is refused; consent is never remembered; the
   consent page always shows the redirect host.
9. The published paths (D-02) never change and gain no aliases.
10. The Voice Budget tests stay, and the hop's answers are unchanged.

## Out of scope (tracked elsewhere)

- Tracking household accounts, so a non-owner connector has history: PLAN-070.
- Plex write-back for anyone but the Server Owner: needs per-person Plex tokens, not planned.
- Operator-minted service tokens (cigar-journal ADR-011): not ported (ADR-091 option 5).
- Seerr requests from a connector: PRD Q-13.

## Rollback

- **Before S7:** revert the feature PR; migration 0078 only adds tables, so an older image runs against it.
- **After S7:** the surface can be taken off the internet without a release by excluding `/mcp` and
  `/oauth` in the three IngressRoutes (haynes-ops, git), the way `/api/mcp` is excluded; the metadata
  documents stay harmless. Disconnecting every app is each user's own action on Connected apps (OPS-016 §4).

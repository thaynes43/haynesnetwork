# 2026-10-07: why owed checks OC-014 and OC-018 failed

Two format-pairing owed checks failed on 2026-10-07 (results in PR #822). Read-only investigation: Loki, the app DB
replica, Kavita's logs, LazyLibrarian's logs and DB (`mode=ro`). Times are UTC unless marked.

## OC-014: the 07:33Z per-minute trip (a defect, fixed in PR "fix(books): pace Google Books requests")

**Cause.** The mint paused 250 ms between attempts, and an attempt is one to four Google Books requests plus up to three
retries each. A run with lookups to make sent about two requests a second and hit the key's per-minute quota about a
minute in. Seven pairing trips in three days, each 55 to 105 s into a run (10-05 10:33Z, 11:32Z; 10-06 07:33Z, 09:33Z,
11:32Z; 10-07 07:33Z, 09:33Z), and the goodreads job at 07:41Z on each of those days. Rate decides it: on 10-05 the 07:33Z
to 09:33Z runs made 100 attempts in 86 to 95 s with no trip, the 10:33Z and 11:32Z runs about 80 in 55 to 57 s and tripped.
The 09:33Z trips also fall inside LazyLibrarian's 09:10Z library scan, which looked up hundreds of unmatched files on the
same key (LazyLibrarian log, `gb.py` lines per minute). The collection-wants pass ends by :29 and resolves through Libretto
(another Google project), so it does not share the minute. A trip latched the mint for the rest of the run (DESIGN-039
D-07): at 07:33:03Z that was after 65 of 100 attempts.

**Fix (DESIGN-039 amendment 2026-10-07).** The GB Call Pacer (T-293): each GB-using cron process sends at most
`GB_CALLS_PER_MINUTE` (60) requests a minute, retries included. The mint waits out one per-minute window a run and carries
on (`quotaWaits`); a second window or a daily one latches as before. The `sync finished` line gains `gbCalls`.

**"Fresh wants first" is implemented** (`missesOf`, the first sort key in `mintPairingWants`): fewest recorded misses
first. A want that had not been looked up since the Mint Backoff shipped (10-06) also has 0 misses, so it ranks with brand
new items, oldest `first_seen_at` first. Of the 61 misses at 07:32Z, 59 were such pre-backoff wants (anchors first seen
07-10 to 07-22) and 2 were new; the 08:34Z run then minted 85 new wants. That cohort is now counted, so this was a
one-off.

**inBackoff 50 to 49.** The want that left is `179dc47e` (*Third Shift - Pact*, Kavita series 291): its anchor was
tombstoned at 22:22Z on 10-06 when Kavita replaced the series with *Shift Omnibus Edition* (2062). A want on a removed
anchor is no candidate, so it is correct.

## OC-018: dropped/revived pairs (not an app defect; Kavita, issue #825)

Every non-zero run is explained by a library change:

| Run | dropped/revived | What changed before it |
|---|---|---|
| 10-06 17:32Z | 2/1 | Kavita Books scans 16:54Z to 17:06Z: The Hunger Games (949) to *Mockingjay* only, Assistant to the Villain (1919) to *Assistant* only |
| 18:32Z | 1/1 | scan 17:57Z flipped both back; (949, Mockingjay audio) dropped |
| 22:32Z | 2/3 | scan 21:40Z flipped both again |
| 10-07 00:32Z | 1/1 | scans 00:02Z to 00:20Z, net back; Mockingjay revived |
| 02:32Z | 3/1 | Audiobookshelf's 17 missing items removed (tombstoned 02:22Z); Percy Jackson revived |
| 04:32Z | 2/3 | Kavita's nightly scan 04:00Z flipped both; Accomplice x2 and The Hunger Games revived |
| 06:32Z | 1/1 | scan 06:20Z (after an EPUB conversion) flipped both back; Mockingjay revived |

Mechanism: Kavita merges EPUBs into a series by the series the EPUB names, LazyLibrarian keeps each book in its own
folder, and Kavita's scan of a changed folder rebuilds such a series from that folder's files alone
(`Removed N volumes from <series> where parsed infos were not mapping`). books-sync re-reads held books whenever Kavita's
`lastChapterAddedUtc` moves (`kavitaHeldRead` 2 to 9 in exactly the books-sync runs before those pairing runs, 0
otherwise), and the matcher follows. It stopped after 06:32Z because Kavita ran no Books scan after 06:20Z, not because
of a deploy (v0.109.4 went live about 14:10Z). It will recur at the next Books scan, at the latest Kavita's nightly one at
04:00Z.

Side effect worth knowing: the want on series 1919 (`57b7d6ad`) changes identity with the series and at 04:32Z pushed the
*Assistant to the Villain* audiobook to LazyLibrarian (`dGy0EAAAQBAJ`, still `Wanted`; the goodreads request `d7017caf`
names the same book). Issue #825 lists 25 Kavita series with the same cleanup since 09-07 and the options; the fix
changes files or the library layout, so it is the owner's call.
